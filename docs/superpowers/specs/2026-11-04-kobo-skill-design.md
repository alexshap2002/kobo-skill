# Скіл «Kobo» для працівників «Будь вільний» і «Є добро» — задум

## Навіщо

Організації переходять на європейський сервер KoboToolbox (`https://eu.kobotoolbox.org`). Кожен працівник має там **власний акаунт** і **власний Claude Code** (окрема підписка). Форми працівник робить у своєму акаунті.

Два **головні акаунти** організацій працівники не використовують:
- `kobo_ymbefree` — «Будь вільний»;
- `kobo_edobro` — «Є добро».

На ці акаунти налаштовані нічний архів і синхронізація з Google Таблицями. Тому **кожна робоча форма має бути поділена з повними правами хоча б з одним головним акаунтом**. Інакше її не буде ні в архіві, ні в таблицях.

Скіл навчає Claude Code працівника цієї системи і робить роботу з Kobo зручною й безпечною:
- форми створюються, змінюються й аналізуються звичайною мовою;
- перед будь-якою зміною робиться резервна копія;
- жодна форма не лишається не поділеною з організацією.

## Для кого

- **Працівники обох організацій.** Здебільшого не технічні, спілкуються українською. Компʼютери Mac і Windows. Працівник може працювати на обидві організації одразу.
- **Адміністратор:** Олександр Шаповалов, Telegram @olexandr_shapovalov. До нього скіл скеровує у складних ситуаціях, зокрема коли треба відновити дані з центрального архіву.

## Цілі

1. **Встановлення один раз** як плагіна Claude Code з публічного GitHub-репозиторію. Оновлення приходять самі.
2. **Перший запуск з підказками.** Claude проводить працівника крок за кроком:
   - де взяти API-ключ Kobo: Account Settings → Security → API Key → Display;
   - ключ зберігається у файл `~/.kobo/token`, а не в чат і не в історію команд;
   - перевірка, що ключ працює саме на європейському сервері;
   - перевірка, що це особистий акаунт, а не головний.
3. **Усе, що вміє API Kobo:**
   - **Форми:** переглянути свої та поділені; створити з опису; змінити; розгорнути (Deploy); архівувати; клонувати.
   - **Доступи:** поділитися з колегами; відкликати доступ.
   - **Відповіді:** вивантажити в Excel або CSV з людськими назвами питань і варіантів; змінити значення; поставити статус перевірки; завантажити фото й файли.
   - **Аналітика:** звіти й дашборди.
4. **Обовʼязкові правила, які скіл виконує завжди:**
   - **Р1. Копія перед зміною.** Перед будь-якою зміною форми чи даних, і перед видаленням, Claude робить локальну копію в `~/Kobo-копії/<назва форми>__<uid>/<дата-час>/`:
     - повний опис форми (`asset.json`);
     - поточну редакцію (`form.xlsx`);
     - усі розгорнуті версії;
     - усі відповіді (JSON для відновлення й Excel для людини).

     Без успішної копії зміна не виконується. Перед **видаленням** до копії додаються також фото й файли відповідей, бо центральний архів їх не зберігає. Для кожної форми лишаються останні 20 копій, старіші видаляються автоматично.
   - **Р2. Нова форма.** Claude обовʼязково питає, для якої організації форма: «Будь вільний», «Є добро» чи обидві. Потім сам ділиться нею з відповідним головним акаунтом з повними правами.
   - **Р3. Перевірка поширення.** Плагін раз на день, на початку сесії Claude Code, і на початку кожної роботи з Kobo перевіряє всі форми, якими **володіє** працівник. Якщо форма не поділена з жодним головним акаунтом або поділена без повних прав, Claude питає, куди поділити, і робить це. Нічого не ділиться мовчки без відповіді працівника. **Відмовитись не можна** (рішення адміністратора): кожна форма, також тестова чи навчальна, має бути поділена. Поки її не поділять, Claude нагадує щодня.
   - **Р4. Розгортання.** Claude нагадує, що таблиця в Google з'являється лише після розгортання (Deploy), і пропонує розгорнути після змін.
   - **Р5. Безпечне редагування форми з даними:**
     - не перейменовувати технічну назву (`name`) питань, у яких уже є відповіді;
     - не змінювати їхній тип;
     - нові питання додавати, а не переробляти старі;
     - перед розгортанням перевіряти форму.

     Якщо працівник наполягає на ризиковій зміні, Claude пояснює наслідок простими словами і робить лише після підтвердження.
   - **Р6. Видалення.** Видаляти форми й відповіді дозволено лише після копії (Р1) і явного «так» від працівника, після того як Claude показав, що саме зникне. Claude пояснює, що:
     - видалена форма 7 днів лежить у кошику Kobo;
     - видалені відповіді Kobo не повертає, але центральний архів має нічну копію.
   - **Р7. Ключ.** API-ключ ніколи не виводиться в чат і не записується в журнали, копії чи звіти.
   - **Р8. Коли щось пішло не так.** Claude пояснює, що робити, і дає контакт адміністратора.
5. **Дашборди й звіти** робляться будь-де, на розсуд працівника (рішення адміністратора): Excel, HTML, Google Таблиці, артефакти Claude.
6. **Повернути форму до копії.** Якщо зміна форми вийшла невдалою, Claude повертає її з локальної копії (опис форми + повторне розгортання), зробивши перед тим нову копію. Втрачені відповіді відновлює адміністратор із центрального архіву.

## Не мета

- Робота з головними акаунтами. Скіл відмовляється працювати з ключем `kobo_ymbefree` чи `kobo_edobro`.
- Адміністрування сервера, архіву й синхронізації. Відновлення з центрального архіву робить лише адміністратор.
- Інші сервери Kobo, крім європейського. Скіл попереджає, якщо ключ від іншого сервера.

## Анти-цілі (провал навіть при «робочому» коді)

- Форма лишилась не поділеною з організацією, і ніхто про це не дізнався.
- Зміна або видалення без копії.
- Ключ потрапив у чат, файл звіту чи репозиторій.
- Claude «загадав» організацію замість того, щоб запитати.
- Працівник злякався технічного тексту: усі повідомлення мають бути людські, без кодів і трасувань.

## Обмеження й рішення, вже ухвалені

- **Плагін** у публічному репозиторії `alexshap2002/kobo-skill`, без секретів. Встановлення:
  - `/plugin marketplace add alexshap2002/kobo-skill`
  - `/plugin install kobo@kobo-skill`
- **«Повні права»** — це всі права, які Kobo дозволяє видати:
  - на форму: перегляд, зміна, керування;
  - на відповіді: перегляд, додавання, зміна, видалення, перевірка.
- **Скрипти** на Python 3 лише зі стандартною бібліотекою, бо мають працювати на Mac і Windows. Якщо Python немає, Claude допомагає його поставити.
- **Мова:** спілкування й повідомлення українською; технічні назви API лишаються англійською.

## Рішення, які ухвалив Claude (перевір)

- Копія перед видаленням містить фото й файли; перед звичайними змінами — ні.
- Скіл сам повертає форму до копії. Відповіді відновлює адміністратор.
- Для кожної форми лишаються останні 20 копій.
- Свого доступу до Google у скілу немає: дашборди робляться файлами (Excel, HTML) або через Google-підключення працівника в Claude. Таблиці, які веде синхронізація, скіл не змінює.
- Скіл відмовляється працювати з ключем головного акаунта.

## Жива перевірка

На особистому акаунті адміністратора на eu.kobotoolbox.org:
- перший запуск;
- створення тестової форми з поширенням на `kobo_edobro`;
- зміна форми з копією і повернення до копії;
- вивантаження даних;
- видалення з копією.

Після перевірки тестова форма, таблиця й записи прибираються.

## Що вирішує будівельник

- Структура `SKILL.md` і довідкових файлів, точні формулювання.
- Набір і інтерфейс команд допоміжного скрипта (backup, share-check, share, export…).
- Як щоденна перевірка показує результат Claude і що робить, коли ключ ще не налаштований: тоді вона мовчить.
- Тести скрипта на фейковому Kobo, як в архіваторі. Жива перевірка на справжньому EU-сервері з особистим тестовим акаунтом.

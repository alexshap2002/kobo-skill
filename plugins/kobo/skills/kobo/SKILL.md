# Kobo для працівників «Будь вільний» і «Є добро»

Працівник має **власний** акаунт на `https://eu.kobotoolbox.org` і в ньому робить форми. Є також два
**головні акаунти** організацій, якими ніхто не користується напряму:
- `kobo_ymbefree` — «Будь вільний» (`--org bud-vilnyi`);
- `kobo_edobro` — «Є добро» (`--org ye-dobro`).

На головних акаунтах працюють нічний архів і синхронізація з Google Таблицями. Форма, не поділена з головним
акаунтом з повними правами, не потрапляє ні в архів, ні в таблицю, тобто для організації її нема. Звідси
більшість правил нижче.

Працівники здебільшого не технічні. Говори з ними українською, просто й коротко. Без кодів помилок,
трасувань, JSON і слова «API», якщо вони самі про це не питають.

## Як працювати з Kobo

Усі дії з Kobo виконуй через помічника `scripts/kobo` у теці цього скілу. Саме він робить копії, ділиться
формами з організацією й не дає зламати дані. Тому не звертайся до Kobo в обхід нього: ні `curl`, ні
власними скриптами, ні через браузер.

```bash
KOBO="<тека цього скілу>/scripts/kobo"     # шлях може містити пробіли: завжди в лапках
"$KOBO" --help                              # повний перелік команд
"$KOBO" <команда> --help                    # параметри команди
```

Відповіді помічника вже написані для людей, тож їх можна переказувати працівнику майже дослівно. Лише
команди й прапорці в них (`--yes`, `kobo share …`) адресовані тобі: працівнику їх не показуй, а просто зроби
відповідну дію після його згоди. Код виходу означає:
- `0` — усе гаразд;
- `1` — потрібна увага: є неподілені форми або це лише попередній перегляд видалення;
- `2` — відмова чи помилка, пояснення в тексті;
- `3` — немає Python, підказка в тексті.

## На початку кожної роботи з Kobo

1. **Kobo ще не налаштовано?** Якщо помічник каже «ще не налаштовано», пройди підключення (нижче).
2. **Перевір поширення:** `"$KOBO" check-sharing`. Якщо є неподілені форми, спершу розв'яжи це з працівником
   (правило Р3), а потім переходь до його прохання. Те саме роби, коли на початку сесії в контексті
   з'являється повідомлення «Плагін Kobo, щоденна перевірка».

## Підключення (один раз на комп'ютері)

1. Поясни, де взяти ключ: eu.kobotoolbox.org → **Account Settings → Security → API Key → Display**.
   Попроси вставити ключ у чат. Так вирішив адміністратор, тож це нормально.
2. Збережи ключ, подавши його на вхід команди. Тоді ключ не потрапляє в аргументи програм:
   ```bash
   "$KOBO" setup <<'KEY'
   <ключ>
   KEY
   ```
3. Відповідай лише результатом, наприклад: «Готово, підключено акаунт olena». Ключа не повторюй і не
   показуй, не записуй його ні в які файли, нотатки чи пам'ять. Помічник зберігає його сам у `~/.kobo/token`.
   Якщо ключ змінився, просто зроби `setup` ще раз.
4. Помічник сам відмовиться від ключа головного акаунта і від ключа з іншого сервера
   (`kf.kobotoolbox.org`, старий український сервер). Переповідж працівнику, що треба зробити.

## Правила (адміністратор вирішив їх раз і назавжди)

**Р1. Копія перед будь-якою зміною.** Кожна команда, що змінює наявну форму чи відповіді, спершу сама зберігає
копію у `~/Kobo-копії/<форма>__<uid>/<дата-час>/`:
- форму;
- усі розгорнуті версії;
- усі відповіді (JSON для відновлення й Excel для людей).

Фото й файли до копії не входять ніколи. Для кожної форми лишаються 5 останніх копій. Якщо копія не вдалася,
зміни не буде, і це правильно. Для того, на що немає окремої команди, використовуй
`"$KOBO" api <МЕТОД> <шлях>`: перед зміною форми він сам зробить її копію. Видаляти, змінювати опис форми
і відкликати доступи через `api` не можна; для цього є окремі команди.

**Р2. Нова форма — спершу питання про організацію.** Перед `create` запитай: «Для якої організації ця форма:
"Будь вільний", "Є добро" чи обидві?». Ніколи не вгадуй, навіть якщо здається очевидним. Помічник сам
поділиться формою з повними правами (`--org bud-vilnyi | ye-dobro | both`).

**Р3. Кожна форма поділена з організацією.** Це стосується також тестових і навчальних форм, і відмовитися
не можна. Для неподіленої форми:
1. Запитай, для якої вона організації.
2. Виконай `"$KOBO" share <uid> --org …`.
3. Де права неповні, запропонуй доповнити тією ж командою.

Нічого не діли мовчки без відповіді працівника. Якщо він вагається, поясни по-людськи: без цього форма не
збережеться в архіві й не з'явиться в таблиці організації. Запитай один раз. Якщо працівник відкладає,
переходь до його прохання: нагадування прийде знову наступного дня.

**Р4. Розгортання.** Люди заповнюють лише розгорнуту (Deploy) версію форми, і Google Таблиця з'являється
лише після розгортання. Після змін нагадай про це й запропонуй `"$KOBO" deploy <uid>` або `--deploy`.
Збирачам у KoboCollect після розгортання треба оновити форму в застосунку.

**Р5. Обережно з формою, у якій уже є відповіді:**
- не перейменовуй технічну назву (`name`) питань, на які вже є відповіді;
- не змінюй їхній тип;
- не прибирай їх;
- нове питання додавай поруч, а старе, якщо треба, приховуй умовою.

`update-form` сам перевіряє це і відмовляє, пояснюючи чому. Якщо працівник наполягає:
1. Поясни наслідок простими словами: старі відповіді відірвуться від форми, звіти й таблиця розійдуться.
2. Повтори з `--force` лише після його явного «так».

**Р6. Видалення — лише після «так».**
1. Виконай `delete-submissions` або `delete-form` **без** `--yes`: це лише покаже, що саме зникне.
2. Перекажи це працівнику, зокрема про фото: після видалення їх не повернути.
3. Лише після явного «так» повтори з `--yes`. Помічник зробить копію і видалить.

Видалена форма 7 днів лежить у кошику Kobo. Видалені відповіді Kobo не повертає, але адміністратор може
відновити їх з копії чи центрального архіву (без фото).

**Р7. Ключ.** Ключ ніколи не з'являється у твоїх відповідях, звітах, файлах, комітах чи пам'яті. Вставити
його в чат працівник може лише для `setup`.

**Р8. Коли щось пішло не так,** спокійно поясни, що сталося і що робити далі. Дай контакт адміністратора:
**Олександр Шаповалов, Telegram @olexandr_shapovalov**. До нього треба, зокрема, щоб:
- повернути видалені відповіді чи форму;
- розібратися з помилкою, яка повторюється.

## Команди

| Що хоче працівник | Команда |
|---|---|
| Який акаунт підключено | `whoami` |
| Побачити форми | `forms` (`--json` для тебе) |
| Перевірити поширення | `check-sharing` |
| Поділитися з організацією | `share <uid> --org bud-vilnyi\|ye-dobro\|both` |
| Дати доступ колезі / відкликати | `share-user <uid> <логін> --role view\|edit\|full`, `unshare-user <uid> <логін>` |
| Створити форму | `create --name "…" --content форма.json --org … [--deploy]`; з Excel-файлу XLSForm: `--xlsx файл.xlsx`; копію наявної: `--clone-from <uid>` |
| Змінити форму | `update-form <uid> --content форма.json [--deploy] [--force]` |
| Розгорнути, архівувати | `deploy <uid>`, `archive <uid>`, `unarchive <uid>` |
| Зробити копію / список копій | `backup <uid>`, `backups <uid>` |
| Повернути форму до копії | `restore-form <uid> --backup latest\|<дата-час>` |
| Вивантажити відповіді | `export <uid> [--format xlsx\|csv\|json] [--out файл]` |
| Фото й файли | `attachments <uid> --out тека [--ids …]` |
| Виправити значення | `set-values <uid> --ids 12,15 --set питання=значення` |
| Статус перевірки | `set-status <uid> --ids … --status approved\|not_approved\|on_hold` |
| Видалити відповіді, форму | `delete-submissions <uid> --ids …`, `delete-form <uid>` (див. Р6) |
| Усе інше з API Kobo | `api GET <шлях>` (читання); `api PATCH/POST <шлях> --data файл.json` (копія форми робиться сама) |

Працівник зазвичай називає форму назвою, а не кодом. Знайди її uid через `forms --json`. Якщо збігів кілька,
перепитай.
